## How to use
> Read this before filling the tables.

- Pick the 4-week or 12-week track based on how much runway the user has.
- Set weekly load to the user's real availability and level. When in doubt, do less, but finish it.
- Every row needs one measurable deliverable: a published notebook, an updated dataset card, a submission logged, a documented refactor. "Measurable" means done or not done, not a score to chase.
- Leave a cell blank rather than padding a week. An empty column is fine; an overloaded week is not.
- Track metrics only if the user provides them; otherwise mark `[not available]`.
- Reminder: consistency and quality beat volume. Shipping fewer, well-documented, reproducible pieces on a steady cadence outperforms a burst of rushed ones. No promise of medals or upvotes; those are not deliverables you control.
